# 麦当劳减肥拍档（mcd-diet-buddy）

> 减脂期想食麦当劳，唔使戒口，换一种吃法就得。
> （减脂期间吃麦当劳不用忌口，换一种吃法就行）
>
> 本文件与 `skill/SKILL.md` 内容一致：根目录呢份方便评委直接睇，`skill/` 嗰份系装进 WorkBuddy 用嘅。

## 安装方式

把本文件放（或复制）到 WorkBuddy 的 Skill 目录：

```bash
mkdir -p ~/.workbuddy/skills/mcd-diet-buddy
cp SKILL.md ~/.workbuddy/skills/mcd-diet-buddy/SKILL.md
```

之后喺对话度直接问就得，唔需要任何 token 配置（token 由 WorkBuddy 嘅 MCP 连接器自己管）。

## 一、核心定位

市面上同类作品都在做「**选什么**」，本 Skill 做「**怎么吃**」呢一层：
同一个汉堡，去酱、去芝士、可乐换无糖、薯条换玉米杯，热量可以砍掉一大截。
而且呢啲动作**唔系我哋估嘅**——全部优先使用麦当劳 MCP 返回嘅**官方替换选项 / 官方特调动作**作为背书。

广告语（对外文案与网页首屏原文照用，一个字都唔改）：
> 麦当劳减肥拍档正式上线啦！只需要使用「麦当劳减肥拍档」，帮你规划好怎么样吃麦当劳能够符合减肥期间的要求，换一种吃法，就可以食得有营养又健康，快D来试下啦！

门面案例（数字系官方营养值实算，唔系手写）：
> 巨无霸三件套 **949 → 456 kcal，慳 493 卡（-51.9%）**
> 中薯条换小杯玉米杯 −236（A 级，−¥0.5）｜可乐换无糖 −147（A 级，¥0）｜去吉士+去巨无霸酱 −110（B 级估算）

## 二、数据分级（严谨性红线，涉及健康建议不可含糊）

- **A 级** = 官方营养数据 / 官方替换选项 / 官方特调动作。营养数值一律以 MCP 返回为准，**不得用记忆数值**。
- **B 级** = 动作官方支持，但热量变化冇官方数值 → 用估算并**标注估算**（如「去吉士」官方有开关，但减几多卡冇官方数）。
- **C 级** = 完全冇官方数据嘅经验估算 → **必须给区间并明示「估算」**（如门店定位、只食馅唔食包）。
- 餐品名匹配唔上营养表就**原样列出**，唔好搵个相似名硬套当数。

## 三、可用麦当劳 MCP 工具（下列结构为真实调用返回，非编造）

1. **`list-nutrition-foods`** —— 官方营养表。返回 **160 条**，字段：
   `productName, nutritionDescription, energyKj, energyKcal, protein, fat, carbohydrate, sodium, calcium`。
   返回系**带表头嘅文本**（唔系纯 JSON），要用 `scripts/parse_nutrition.py` 转成 `data/nutrition.json`
   （字段 name/kcal/protein/fat/carb/sodium/calcium，按 name 去重 → **158 条**）。**所有热量以呢份为准（A 级）。**

2. **`query-meal-detail`** —— **套餐详情（本作品核心）**。参数 `storeCode / code / orderType / beType`。
   返回 `rounds[]`（套餐组成轮次）+ `choices[]`（每轮可换选项，含 `diffPrice` 价差、`isDefault`、`supportModify`）
   + `modification.items[].values[]`（官方特制项，如去酱、去冰、换燕麦奶；每项带 `selectedQuantity`、
   `selectedKey` / `unselectedKey`）。

   **实测关键结构（巨无霸三件套 `code=9900005466`）：**
   - round1 新升级巨无霸：`supportModify=true`，`modification.items[0].values` 含 巨无霸酱 / 吉士 / 生菜 / 酸黄瓜 / 洋葱粒，
     每项 `selectedQuantity=1` 可关，`selectedKey="0-1"` / `unselectedKey="0-0"` → **官方支持去酱 / 去芝士**。
   - round2 小食：中薯条(default) 可换 小杯玉米杯(`diffPrice="- ¥0.5"`) / 大薯条 / 脆脆薯条 → **官方支持换小食**。
   - round3 饮料：可乐中杯(default) 可换 无糖可口可乐中杯(`diffPrice="+ ¥0"`) / 雪碧 / 纯牛奶 / 苹果汁；
     另有冰量组 标准 / 去冰 / 少冰 / 多冰 → **官方支持换无糖 + 去冰**。

   ⚠️ **四件套有 4 轮**（巨无霸四件套 `9900000888`：巨无霸 ｜ 小食 ｜ 小食 ｜ 选择套餐内饮料），
   第 3 轮**唔系**饮料轮 → **必须按轮次名识别，唔好写死 `rounds[2]`**。
   ⚠️ 全反向嘅轮次（全部可换项都会多卡，如麦乐鸡4块换 V 翅 +22）**保持默认，唔好倒扣**。

3. **`query-nearby-stores`** —— 附近门店。参数 `city / keyword / searchType / beType`。
   返回 `storeCode` / `storeName` / `address` / `distance` / `businessStatus` / `businessStartTime` / `businessEndTime`。
   ⚠️ **官方唔返回门店精确经纬度**（`longitude` / `latitude` 恒为 `0.0`）→ 距离只可以当**官方相对查询地标**嘅距离，
   相对用户位置只能靠地标近似，属 **C 级估算，必须标注**。

4. **`query-meals`** —— 门店菜单。参数 `storeCode / orderType / beType`。
   返回分类与餐品对象（`name` / `image` / `currentPrice` / `originalPrice`）。
   ⚠️ **门店非营业时间会报错 600057** → 拉唔到菜单嘅店标「未预载菜单」，**唔可以用第间店嘅数据顶替**。
   ⚠️ 唔同城市菜单唔同（实测上海无麦辣鸡腿汉堡三件套）→ **唔好假定全国菜单一致**。

> `calculate-price` / `create-order` 本 Skill **唔调用**（涉及真实下单，本作品只做规划与建议）。
> 但结构上已 ready：`selectedKey` / `unselectedKey` 正系呢两个工具食嘅特调 key。

## 四、三个功能层工作流

### 1. 今日食咩（`scripts/daily_plan.py`）
- **输入**：每日热量预算(kcal) + 目标（均衡 / 高蛋白 / 低钠）+ 是否避开高热量小食。
- **处理**：从官方营养表按类别（早餐 / 主食 / 小食 / 饮料）挑选贴近餐段预算嘅餐品；
  **三个目标必须给出唔同结果**（系数唔同，跑完要自检，唔可以三个目标出同一份）。
- **硬约束（超限必须主动提醒，唔可以静默）**：
  - 全日钠 ≤ **2000 mg**，单餐钠 ≤ **1100 mg**（主角餐可放宽到 `max(1100, 主角钠 × 1.15)`）；
  - 蛋白下限 = `kcal / 25`；
  - 每餐有热量下限（**唔可以「早餐只畀一杯嘢饮」**），早餐优先早餐品类；
  - 封杀高热量小食（派 / 大薯条 / 麦旋风 / 含糖饮料）并讲「呢啲我帮你过滤咗」及原因；
    **无糖可乐、玉米杯唔可以误杀**。
- **输出**：一日三餐（每项官方 kcal + 蛋白 + 改造建议 + A/B 标注）+ 全日钠/蛋白汇总 + 警告。

### 2. 点食先减肥卡（`scripts/transform_engine.py`）
- **输入**：一个套餐。已内置 **12 个真实在售官方套餐**（8 个三件套 + 巨无霸四件套 / 板烧鸡腿堡四件套
  + 酥脆无双套餐（官方 500 大卡线）+ 麦乐鸡经典中套餐），全部来自 `query-meal-detail`，
  含官方 `rounds/choices/modification` 与现价。
- **处理**：
  - 按轮次**名**识别 主食 / 小食 / 饮料（支持四件套多个小食轮），**唔好按下标硬取**；
  - 餐品名归一化后再匹配营养表（半角/全角括号、尺寸缺省取中杯、别名表），**匹配唔上就列出，唔硬套**；
  - 每轮取最省嘅官方替换 + 可叠加嘅官方去配料（只计 ≥15 卡，免得生出「省 5 卡」嘅琐碎开关）+ 经验型动作（标 C，给区间）。
- **输出**：改前/改后餐品与热量、热量差、价格差（用官方 `diffPrice`）、A/B/C 级标注，按省热量排序。
- **实测结果**：巨无霸三件套 949 → 456 kcal（省 493，-51.9%，门面）；麦香鱼套餐 761 → 258 kcal
  （省 503，-66.1%，降幅最大）；酥脆无双套餐省 0 kcal（官方 500 大卡线内，**唔系漏计**，要如实标注）。

### 3. 揾门店（`scripts/build_stores.py`）
- **输入**：城市 + 地标关键词（如「广州 / 中山大学南校区」）。
- **处理**：`query-nearby-stores` 拉门店；对已预载菜单嘅门店，用官方菜单 code 逐间比对 12 个改造套餐，
  **价格用呢间店嘅官方价**；拉唔到菜单嘅店标「未预载菜单」，**唔用别店数据顶替**。
- **已落盘**：广州 / 深圳 / 上海 / 北京 4 城共 **20 间**官方门店，其中 2 间已预载菜单（86 / 76 项）。
- **输出**：门店名 / 地址 / 营业时间 / 在营状态 / 距地标距离（**C 级，注明唔系相对用户位置**）/ 呢间店有售嘅改造套餐及门店价。

## 五、数据快照与刷新

三份**官方快照**（唔好手改派生文件，会被 build 覆盖）：

| 文件 | 来源 Tool | 刷新 |
|---|---|---|
| `data/nutrition.json`（158） | `list-nutrition-foods` | 重新调 MCP → 存 `data/nutrition_raw.txt` → `python scripts/parse_nutrition.py` |
| `data/menu.json`（123） | `query-meals`（storeCode=1400028） | 挑**营业中**门店重新调 → 存 `data/menu_raw.json` → `python scripts/build_menu.py` |
| `data/combos.json`（12） | `query-meal-detail` | 逐 code 重新调 → 同步改 `scripts/build_combos.py` / `add_combos_v2.py` → 各跑一次 |

改完快照**一定要再跑** `python scripts/build_site.py`，`web/index.html` 先会更新（佢系构建产物）。

## 六、执行纪律

- 营养数值只用 MCP 官方返回，**不凭记忆**。
- 匹配唔上营养表嘅餐品**单独列出**，唔硬套相似名。
- C 级永远「**区间 + 估算**」。
- 官方接口嘅限制（冇经纬度、非营业时间报错、各地菜单唔同）要**如实告知用户**，唔掩饰、唔编造、唔用别店数据顶替。
- **唔向用户索取 token**，唔把 token 写进任何文件（连接由 WorkBuddy MCP 连接器管）。
- 输出底部带免责声明：营养数据来自麦当劳官方 MCP，仅供参考，实际以门店为准；减脂与钠摄入请遵医嘱；
  本项目为参赛作品，与麦当劳官方无隶属关系。
