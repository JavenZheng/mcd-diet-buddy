# 麦当劳减肥拍档（mcd-diet-buddy）

## 一、核心定位
减脂期想食麦当劳，唔使戒口，换一种吃法就得。
市面上同类作品都在做「选什么」，本 Skill 做「怎么吃」这一层：同一个汉堡，去酱、去芝士、可乐换无糖、薯条换玉米杯，热量可以砍掉一大截。优先使用麦当劳 MCP 返回的**官方替换选项 / 官方特调动作**作为背书。

广告语（对外文案与网页首屏原文照用，一个字都唔改）：
> 麦当劳减肥拍档正式上线啦！只需要使用「麦当劳减肥拍档」，帮你规划好怎么样吃麦当劳能够符合减肥期间的要求，换一种吃法，就可以食得有营养又健康，快D来试下啦！

## 二、数据分级（严谨性红线，涉及健康建议不可含糊）
- **A 级** = 官方营养数据 / 官方替换选项 / 官方特调动作。营养数值一律以 MCP 返回的官方数据为准，不得用记忆数值。
- **B 级** = 动作官方支持，但热量变化无官方数值，需手工补录并注明来源（如「去酱」官方支持去酱，但去酱减多少 kcal 无官方数，用估算并标注）。
- **C 级** = 无官方数据的经验估算，必须给区间并明示「估算」（如门店定位）。
- 餐品名匹配不上营养表就列出来，不要用相似名字硬套。C 级数字永远保持「区间 + 估算」标注。

## 三、可用麦当劳 MCP 工具（以下结构为真实调用返回，非编造）
1. `mcp__mcd-mcp__list-nutrition-foods` —— 官方营养表。返回 `[160]` 条餐品，字段：
   `productName, nutritionDescription, energyKj, energyKcal, protein, fat, carbohydrate, sodium, calcium`。
   返回为带表头的文本（非纯 JSON），需用 `scripts/parse_nutrition.py` 转成 `data/nutrition.json`（字段 name/kcal/protein/fat/carb/sodium/calcium，按 name 去重 → 158 条）。
2. `mcp__mcd-mcp__query-nearby-stores` —— 附近门店。参数 `city / keyword / searchType / beType`。
   返回门店编码(storeCode)、名称、地址、营业时间、是否在营。**实测约束：官方唔返回门店精确经纬度（longitude / latitude 恒为 0.0）**，所以「距离」只能当作官方相对查询地标嘅距离；要做到「相对用户位置」只能靠地标近似，属 **C 级估算**，必须标注。
3. `mcp__mcd-mcp__query-meals` —— 门店菜单。参数 `storeCode / orderType / beType`。
   返回分类与餐品对象（name / image / currentPrice / originalPrice 等）。**实测约束：门店非营业时间会报错（600057）**，拉唔到菜单嘅门店要标「未预载菜单」，**唔可以用第间店嘅数据顶替**。
4. `mcp__mcd-mcp__query-meal-detail` —— **套餐详情（核心）**。参数 `storeCode / code / orderType / beType`。
   返回 `rounds`（套餐组成轮次）+ `choices`（每轮可换选项，含 `diffPrice` 价差、`isDefault`、`supportModify`）+ `modification`（单品/选项的官方特制项，如去酱、去冰、换燕麦奶）。
   **实测关键结构（巨无霸三件套 code=9900005466）：**
   - round1 新升级巨无霸：`supportModify=true`，modification.items 含 巨无霸酱/吉士/生菜/酸黄瓜/洋葱粒，每项 `selectedQuantity` 可关 → **官方支持去酱/去芝士**。
   - round2 小食：中薯条(default) 可换 小杯玉米杯(diffPrice -¥0.5)/大薯条/脆脆薯条 等 → **官方支持换小食**。
   - round3 饮料：可乐中杯(default) 可换 无糖可口可乐中杯(diffPrice ¥0)/雪碧/纯牛奶/苹果汁；冰量可选 标准/去冰/少冰/多冰 → **官方支持换无糖 + 去冰**。
   - **四件套结构**：rounds 有 4 轮（主食 / 小食 / 第二件小食 / 饮料），第 3 轮唔系饮料轮，要按轮次名识别，唔好写死 `rounds[2]`。
5. `mcp__mcd-mcp__calculate-price` / `mcp__mcd-mcp__create-order` —— 算价/下单（带特调 key 时使用）。

## 四、三个功能层工作流
### 1. 今日食咩（`scripts/daily_plan.py`）
- 输入：每日热量预算(kcal) + 目标(均衡 / 高蛋白 / 低钠) + 是否避开高热量小食。
- 处理：从官方营养表按类别(早餐/主食/小食/饮料)挑选贴近餐段预算的餐品；三个目标必须给出**唔同**结果（唔同目标系数唔同，跑完要自检）。
- 硬约束（**超限必须主动提醒，唔可以静默**）：
  - 全日钠 ≤ 2000 mg，单餐钠 ≤ 1100 mg（主角餐可放宽到 `max(1100, 主角钠 × 1.15)`）；
  - 蛋白下限 = `kcal / 25`；
  - 每餐有热量下限（唔可以「早餐只畀一杯嘢饮」），早餐优先早餐品类；
  - 封杀高热量小食（派 / 大薯条 / 麦旋风 / 含糖饮料）并说明「呢啲我帮你过滤咗」及原因；**无糖可乐、玉米杯唔可以误杀**。
- 输出：一日三餐（每项官方 kcal + 蛋白 + 改造建议 + A/B 标注）+ 全日钠/蛋白汇总 + 警告。

### 2. 点食先减肥卡（`scripts/transform_engine.py`）
- 输入：一个套餐。已内置 **12 个真实在售官方套餐**（8 个三件套 + 巨无霸四件套 / 板烧鸡腿堡四件套 + 酥脆无双套餐（官方 500 大卡线）+ 麦乐鸡经典中套餐），均来自 `query-meal-detail`，含官方 rounds/choices/modification 与现价。用户可在网页内切换套餐。
- 处理：
  - 按轮次**名**识别主食 / 小食 / 饮料（支持四件套多个小食轮），唔好按下标硬取；
  - 餐品名归一化后再匹配营养表（半角/全角括号、尺寸缺省取中杯、别名表），**匹配唔上就列出，唔硬套相似名**；
  - 每轮取最省嘅官方替换 + 可叠加嘅官方去配料 + 经验型动作（经验型标 C，给区间）。
- 输出：改前/改后餐品与热量、热量差、价格差（用官方 `diffPrice`）、A/B/C 级标注，按省热量排序。
- 实测结果：巨无霸三件套 949 → 456 kcal（省 493，-51.9%）；麦香鱼套餐 761 → 258 kcal（省 503，-66.1%，降幅最大）；酥脆无双套餐省 0 kcal（官方 500 大卡线内，**唔系漏计**，要如实标注）。

### 3. 揾门店（`scripts/build_stores.py`）
- 输入：城市 + 地标关键词（如「广州 / 中山大学南校区」）。
- 处理：`query-nearby-stores` 拉门店；对已预载菜单嘅门店，用官方菜单 code 逐间比对 12 个改造套餐，**价格用呢间店嘅官方价**；拉唔到菜单嘅店标「未预载菜单」，**唔用别店数据顶替**。
- 已落盘：广州 / 深圳 / 上海 / 北京 4 城共 **20 间**官方门店，其中 2 间已预载菜单（86 / 76 项）。实测沪穗菜单唔同（如上海无麦辣鸡腿汉堡三件套）——**唔好假定全国菜单一致**。
- 输出：门店名 / 地址 / 营业时间 / 在营状态 / 距地标距离（C 级，注明唔系相对用户位置）/ 呢间店有售嘅改造套餐及门店价。

## 五、执行纪律
- 营养数值只用 MCP 官方返回，不凭记忆。
- 匹配不上营养表的餐品单独列出，不硬套相似名。
- C 级永远「区间 + 估算」。
- 官方接口嘅限制（无经纬度、非营业时间报错、菜单唔同）要**如实告知用户**，唔掩饰、唔编造、唔用别店数据顶替。
- 唔向用户索取 token，唔把 token 写进任何文件。
- 输出底部带免责声明：营养数据来自麦当劳官方 MCP，仅供参考，实际以门店为准；减脂与钠摄入请遵医嘱；本项目为参赛作品，与麦当劳官方无隶属关系。
